#### Issue (non-test-execution failure)

All 225 other tests passed. The failure is **non-deterministic**: running the suite in isolation (`--filter TraceHygieneTests`) produces 2/2 passing. Running the full suite produces 1/2 failing.

#### Root Cause Analysis

**Symptom:** `instanceOverrideFileURL` on `TraceLogger.shared` is left non-nil, so `effectiveFileURL` returns the instance override (a temp path) instead of the TaskLocal override. The `MockResponsesClient` uses that same temp path, but the test's mtime check targets the production path — so production is NOT written to. The test correctly fails because its mtime check DID observe a production trace write.

**Diagnosis:** The culprit is `TraceLoggerInstanceOverrideTests`, which calls `await TraceLogger.shared.setFileOverride(tmpURL)` at the start of two of its three tests without a `defer` to restore nil. Although the test suite carries `@Suite(.serialized)`, Swift Testing serializes per-suite, not globally across all suites. `TraceLoggerInstanceOverrideTests` runs before `TraceHygieneTests` (alphabetical ordering) and leaves `instanceOverrideFileURL` set to a stale temp path from a previous test run. When `TraceHygieneTests.taskLocalIsolatedBridgeTestDoesNotPolluteProductionTrace` executes inside `withTaskLocalIsolation`, the instance override is non-nil and takes priority over the TaskLocal, redirecting the bridge's `MockResponsesClient` stream-events to that stale path instead of the TaskLocal-controlled path. Since the stale path no longer exists (it was cleaned up by a previous `defer` in `TraceLoggerInstanceOverrideTests`), the `MockResponsesClient` writes to the production path instead.

**Scope:** All Phase 1-6 tests pass. The new Phase 7 tests all pass in isolation. The hygiene regression is isolated to the interaction between `TraceLoggerInstanceOverrideTests` and `TraceHygieneTests` under global suite ordering.

**Required fix (not applied — read-only reporter):** Add `defer { Task { await TraceLogger.shared.setFileOverride(nil) } }` to the two affected tests in `TraceLoggerInstanceOverrideTests.swift` (`instanceOverrideSurvivesTaskDetached` and `taskLocalOverrideBeatsInstanceOverride`), matching the pattern already used in `withInstanceOverride` in `TraceIsolation.swift`.
