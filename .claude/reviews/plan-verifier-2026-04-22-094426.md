### [运行时 Regression 推理 1]
**假设 regression**：用户在 Claude Code 里发纯文本一轮请求，Bridge 新流水执行：
- `streamEvents` yield `response.output_text.delta` 3 次 → encoder emit 3 条 `content_block_delta`（延迟可控，OK）
- `response.output_item.done` (type=message) 到达 → plan 第 381 行 `encoder.closeOpenBlock()` → `content_block_stop`
- `response.completed` 到达 → 记录 usage
- stream 结束 → `finish(stopReasonHint: .endTurn)` → `message_delta + message_stop`

**操作路径**：Claude CLI `--bare -p "hi"` → daemon accepts → bridge.handleMessages → `runStreamingTurn` → 上游 stream → writer → NWConnection. 
**潜在问题**：`response.completed` 的 handling 不做任何 wire emit；但若 `response.completed` 在 `response.output_item.done` (message) 之前到达（顺序颠倒），plan code 仍先 record usage 再继续。对文本 only turn OK。真正 regression 风险：若 upstream 产生 `response.output_text.delta` 但 `response.output_item.done` 缺失（docs/scheme3/08 §4.4 暗示 `response.output_item.done` 可能被跳过），plan 不会 close text block，CLI 等不到 `content_block_stop` 就收 `message_delta`，违反 Anthropic wire。

**计划覆盖**：⚠️ 未覆盖 → 计划需补充：
- Task 5 步骤 4 在 `response.completed` 分支（或 loop 结束后）兜底 `try await encoder.closeOpenBlock()`，保证在 finish 前 block 已关闭；plan 第 321 行说 "finish：close open block" — 但 finish 目前只描述写 message_delta/message_stop；需补 "先 closeOpenBlock" step
