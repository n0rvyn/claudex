## Part A: 视觉规范

### A1. 间距与布局

#### Hardcoded spacing not on AppSpacing scale
The project has no `AppSpacing` token enum; all spacing is direct `CGFloat` values. No violations detected since there is no token system to violate. Layout uses consistent numeric values (multiples of 2/4/8/12/14/16) throughout.

**PASS** — no hardcoded non-8pt-multiple spacing found.

Touch targets: all buttons use system defaults (~44pt). The delete `Button` in `RoutingRuleDraftRow` is an icon-only button (16x16 SF Symbol). This is a touch-target concern for accessibility.

#### MBCard section-level background rule
`routingInsightsSection` uses `MBCard(padding: 10, background: MBColor.paperDim)` as its section container. `MBCard` internally applies `frame(maxWidth: .infinity)`, so the section does not need an additional frame modifier. This is handled correctly.

### B5. 导航状态保持

#### Routing drafts not persisted on dismiss
`UpstreamSettingsTab` — drafts (`routingRulesDraft`, `fallbackRouteDraft`, `advisorRouteDraft`) are `@Published` on `AppModel`. When the user navigates away from the Upstream tab without saving, the drafts remain in `AppModel`. If the user returns to the tab, the drafts still reflect unsaved changes (since `AppModel` is shared across all tabs via `@ObservedObject`). There is no mechanism to discard unsaved changes when switching tabs. If the user made changes and wants to discard them, they must either reload config (via "Reload config" button) or re-navigate tabs which does NOT reset drafts.

**Warning**: If a user edits routing rules, switches to a different tab, then returns, their unsaved edits are still present. This is acceptable behavior for a Settings panel (common macOS pattern) but could be confusing. No explicit "Discard changes" button exists. The "Reload config" button restores from disk.

**No blocking issue.**
